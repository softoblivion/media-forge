# UI design — Liquid Glass for Media Forge

Owner: ui worker. Scope: everything under `src/media_forge/ui/`. The JS <-> Python contract is `docs/BRIDGE_API.md`;
this document describes the material, the design system, the motion and the background of the page that codes
against it. The design system itself (tokens, fonts, material, springs, controls, overlays, toasts, title bar,
background, the version pill with the update popover) is the shared Liquid UI kit, vendored at
`src/media_forge/ui/vendor/liquid_ui/` (version in its `VENDORED.txt`); its owning document is
`D:\Projects\_shared\liquid_ui\docs\LIQUID_UI.md`. This document records what Media Forge uses, its own screen and
where it differs.

## 2. Material

### 2.1 Lens — kit `js/glass.js`, `css/glass.css`

`new Lens(el, preset)` builds one SVG filter per element: `feGaussianBlur -> feDisplacementMap -> feColorMatrix`,
applied with `backdrop-filter: url(#lgN) <preset css>`; the displacement map is a convex squircle bezel traced with
Snell's law (n = 1.5), regenerated by a `ResizeObserver`, cached (LRU, 80 maps), half resolution above 120 000 px.
Strength 0..1 scales displacement, frost and saturation together; 0 sets `backdrop-filter: none`. Layers inside a
lens: refracted backdrop, tint (`--lens-tint`), press tint (`::before`), content, specular rim (`.lg-rim`, conic
gradient lit at the global light angle `--la`, which drifts with the pointer).

| Preset | Used by | Notes |
|---|---|---|
| `pill` | Start button | whole surface curved |
| `capsule` | version pill, window cluster (gear, minimize, close), footer counters capsule, toasts | |
| `panel` | empty-state drop target | half-resolution map |
| `sheet` | settings sheet, update popover, drop veil | deep frost (14 px) for legibility |
| `droplet` | segmented indicators and switch thumbs, only while pressed | strength 0 at rest |

### 2.2 Cheap glass — `.glass-lite`

`backdrop-filter: blur(18px) saturate(1.7) brightness(1.04)` plus a quieter rim. Used for every file card (any number),
the FFmpeg banner and the menus (menus use a near-opaque tint).

### 2.3 Rules

- Refracting surfaces at once: steady 4 (version pill, window cluster, counters capsule, Start) or 3 + the empty-state
  panel when the list is empty; plus up to 3 toasts, one sheet or popover, the drop veil while dragging, and one
  droplet while a control is pressed. Never more than about 12.
- No glass on glass: buttons inside the window cluster, the counters capsule, the sheet and the cards are fills; the
  droplets lift into glass only while pressed (a lens is a backdrop root, so they refract the labels under them).
- Backdrop roots: no `opacity < 1`, `filter`, `mask` or `clip-path` on an ancestor of a lens or a glass-lite card. The
  drop veil therefore fades its dim layer and its lens separately, never their parent; the footer menu lives outside
  the counters capsule; entrance animations fade only elements that are lenses themselves. Masks are used only on
  elements whose descendants are meant to see their own content: the settings scroller and overflowing chip rows.
- Tint only the primary action: Start while it can start (accent glass), Done (mint), the empty state's "Choose
  files", and Download / Restart to update in the update panel.
- Legibility: white ink in alpha steps, a 1 px text shadow on lenses, `--well` under inputs and long text.
- `prefers-reduced-transparency`: near-opaque tints, glass-lite without blur. `prefers-contrast: more`: solid rims.

## 4. Motion — kit `js/motion.js`

One spring solver (semi-implicit Euler, 240 Hz sub-steps, `response` / `damping`), one shared rAF ticker that runs only
while a spring moves, and `springEasing` / `springAnimate` for compositor animations with a CSS `linear()` easing.

| Spring | response / damping | Used for |
|---|---|---|
| snappy | 0.30 / 0.80 | droplet lift, switch press |
| bouncy | 0.42 / 0.62 | droplet travel, toasts, card insert, Start width |
| jelly | 0.38 / 0.42 | release wobble of a press |
| press | 0.20 / 0.75 | squish while pressed |
| sheet / sheetClose | 0.52 / 0.80, 0.34 / 1.00 | sheet and popover morph, card collapse |
| materialize | 0.45 / 0.92 | lensing ramp in / out |
| expand (list.js) | 0.46 / 0.86 | card drawer height |

Behaviours:
- Gel press on every button and lens (`gel(el)`): squish, lighter tint while pressed, jelly release.
- Card expand: the drawer's height animates 0 -> content height with the expand spring (WAAPI), the panel fades in
  from 8 px above; collapse runs `sheetClose` and then destroys the panel (its droplet lenses go with it). One card is
  open at a time. After opening, the list scrolls just enough to show the panel above the footer.
- Card insert: drop in from 16 px with `bouncy`, staggered 40 ms for a batch. Removal: fade and shrink, then the height
  collapses (the following cards move up).
- Running card: a liquid layer (`.card-liquid i`) moves by `translateX((p - 1) * 100%)` with a 72 px soft leading
  edge (mask), a faint sheen loop only while running; on done it fills, turns mint and fades (1.4 s).
- Start pill: label "Start" / "Start N files" -> "k of n · speed" over a liquid level of the whole batch -> mint
  "Done" for 2.6 s -> back. The width springs to the content (min 148 px, 176 px while running, max 46 % of the footer).
  Entering the progress state resets the level without travel.
- Sheets and popovers grow out of their control (clip-path inset spring, lensing ramp, content fades in late); Esc
  or the scrim closes them back into the origin.
- Toasts drop from the top centre with scale and lensing ramp, FLIP-stacked, at most 3.
- Drop veil: the sheet lens materialises over the whole window, a ripple ring expands from the pointer on dragenter
  (1.1 s), the tray icon bobs; on drop it squashes once and the veil fades.
- Number rolls in the stepper; segmented droplets stretch with velocity.
- `prefers-reduced-motion`: springs critically damped and short, no CSS loops (scene, sheens, bobbing, pulse), no
  drawer or insert animation, the speck canvas stops.

## 5. Background — kit `js/background.js`, `css/scene.css`

The starting point was a plain vertical gradient from black to deep navy. It stays the base; five layers give it
depth. `js/main.js` passes the four colour fields below as `initBackground(#scene, { fields })` (the kit's other
options keep their defaults).

| # | Layer | Technique | Cost |
|---|---|---|---|
| 1 | Base gradient black -> `#0a1e3f` | `background` of `#scene` | static |
| 2 | Four colour fields: cobalt `#2f62ff` (left middle, 92 vmax), teal `#12b8b0` (bottom right), violet `#7a48ff` (top right), ember `#ff8a4a` at 12 % (bottom left) | radial gradients on divs, CSS keyframes on `transform` (translate + scale), periods 46 / 58 / 72 / 78 s, alternate, negative delays | compositor |
| 3 | Contour rings around two centres + nine caustic lines | one static SVG (portrait viewBox 960 x 1280, `slice`), 96 s drift loop on `transform` | compositor |
| 4 | 40 rising specks (5 tints, 3-15 px soft glow, sway) | one canvas at half the CSS resolution (upscaled = soft), sprites drawn with `drawImage`, additive blend, 30 fps cap | ~40 draws per frame while visible |
| 5 | Light sweep: a soft diagonal band crosses the window in ~5.7 s once every 26 s | CSS keyframes on `transform` | compositor |
| 6 | Vignette (radial + a top shade) and a static grain tile (160 px, generated once) | static | none |

Pointer parallax: layers 2, 3 and 4 sit in oversized wrappers that translate by up to 10 / 5 / 16 px against the
pointer, eased by a 1.6 s `transform` transition (rAF-throttled pointer handler; no per-frame JS).

Pausing: the speck rAF loop stops and every CSS loop holds (`#scene.is-paused`, `html.is-still` for the page's own
loops) when the document is hidden, the window is unfocused (the bridge's `window` event or the browser blur), after
90 s without input, or with `prefers-reduced-motion`. No layer reads or writes layout per frame; at idle the scene
costs nothing. While visible and active, the cost is the compositor drift plus the half-resolution canvas; the
lenses re-filter their small backdrop each frame (4 steady surfaces).

Every change is a one-key patch: `set_item_settings(id, patch)` for a card, `set_settings({defaults: {<kind>:
patch}})` for the defaults. The panel applies the change locally until the answer arrives, then shows the returned
(normalised) settings; a refusal shows the sentence as a toast and restores the last confirmed values. A sequence
number drops stale answers; item events do not move a panel while its own patch is in flight.

### 6.3 Updates (UpdateStatus.stage)

The version pill, the update popover, the update toasts and the "Updates" rows of the settings sheet are the kit's
update control (`mountUpdateControl`; stages, copy and behaviour in LIQUID_UI.md, section 7; its bridge contract,
section 8, matches BRIDGE_API sections 2, 3.5, 3.7, 3.8 and 4). Media Forge passes: product "Media Forge", the
State's version, update status and settings, the restart warning "Files in progress stop
when the app restarts" (shown with "Restart anyway" while files are queued or running), `onStatus` (store `update`)
and `onSettings` (store `settings`); `js/main.js` forwards every confirmed `settings` to `setSettings`.

In short: idle / up_to_date "Check for updates"; checking with an indeterminate bar; available with Installed /
Latest rows, release notes and a tinted "Download"; downloading with a bar, percent and sizes; ready with a tinted
"Restart to update" (disabled when `can_apply` is false); error with the message and "Try again". The first
`available` of a version raises one toast with "View" (not when automatic download is on: the shell downloads by
itself, ARCHITECTURE 5.7); `ready` one sticky toast with "Restart". The page never downloads or restarts on its own.
Release-note links open in the default browser through `open_url`.

### 6.4 Keyboard

Ctrl+O choose files; Ctrl+Enter start; Delete removes the focused card (focus moves to the next one); Enter / Space on
a card opens or closes its panel; Up / Down move between cards; Esc closes the top overlay or menu, else closes the
open card; arrows move segmented selections; Ctrl+V of copied Windows paths (outside inputs) adds them through
`add_files`. Visible `:focus-visible` rings everywhere.

## 7. Runtime notes

- ES modules do not load from `file://`: the shell serves the folder over `http://127.0.0.1:<port>/`. Dev preview:
  any static server on the `ui` folder, open `index.html?mock=1`. The mock is used with `?mock=1` or when pywebview
  does not appear within 1.5 s.
- Mock URL flags: `items=N` (N ready files), `demo=1` (one file per state: done, failed, FLAC with a size limit,
  running, unreadable, ready), `fast=1` (jobs 4× faster), `update=available|uptodate|error` (launch check result),
  `nvenc=0` (no NVIDIA GPU: GPU options disabled), `ffmpeg=downloading` (banner, Start waits). The mock persists
  settings in `localStorage` (`media-forge.mock.settings`), probes in 300-900 ms with generated thumbnails, runs jobs
  with plausible stages / speed / ETA, fails one job in ten, mimics size limits, implements normalisation exactly as
  BRIDGE_API 3.4, re-queues `error` (read) and `done` items in `start([id])` with a new numbered output name, starts an
  item at once in `start_now(id)` (a queued one leaves the queue; the parallel limit is ignored), opens
  `open_url` links with `window.open`, and cycles the update status on demand (manual check finds 0.2.0; Download;
  Restart).
- Mock-only hook: `_simulate_drop(files)` (underscored, not part of the contract): browser drops become items by name
  through the `items_added` event, like the shell's drop listener.
- Bridge expectations the page relies on (BRIDGE_API): `window.mediaForge.dispatch(name, payload)` is the only hook;
  `item` events may arrive for ids the page has not seen (they create the card); `start(ids)` returns the queued ids.
- The page makes no network request: fonts (the kit's `fonts/`) and icons are local, thumbnails are data URLs.
- The kit copy is updated only by syncing the master (`vendor-sync.ps1 -Lib liquid_ui -Project media-forge`); a fix
  made in the copy is ported to the master the same day.
- Screenshots of a hidden browser pane: rAF and WAAPI pause there, so springs and entrances hold their first frame;
  finish finite animations first (`document.getAnimations().forEach(a => a.finish())`).
- Every lens owns one `<filter>`; panels, toasts and controls destroy their lenses when removed.
- Sound when done (the page's job per BRIDGE_API 3.5; the shell plays nothing): `js/sound.js` synthesises a short two-note chime with Web Audio on `batch_done` with at least one
  finished file, at most once per second; no audio file is shipped. `open_when_done` is the shell's job; the page
  only shows the switch.

## 8. Copy rules

- Neutral and factual (`_workspace/CONVENTIONS.md`, "UI copy"): say what a control does or what happened, no filler,
  no exclamation marks. English (US), sentence case: "Choose files", "Start", "Clear done", "Show in folder", "Open",
  "Retry", "Apply to all video", "Remove", "Start now", "Cancel", "Check for updates", "Restart to update", "Try again".
- The bridge's kind `image` reads as "Photo" (chip), "photos" (Apply to all photos, counts). Format and codec labels
  are shown exactly as `Options` gives them; summaries shorten "MP3 · audio only" to "MP3".
- Plurals through `plural()` / `nFiles()` / `nKind()`; sizes in B / KB / MB / GB, percentages with a no-break space
  ("19 %"), ETA "1 min 12 s left", durations "1:12".
- Strings from the shell (errors, toasts, UpdateStatus.message) are shown as received.
